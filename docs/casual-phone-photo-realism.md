# Casual phone-photo realism

This is a small shared-prompt refinement based on the user's written review of a successful outdoor selfie. No source image was attached for independent inspection, and no paid image was generated during development. It is not a claim that the reported visual defects have been empirically eliminated.

The existing shared image builder already requested ordinary phone photography. It now provides more specific, conditional camera guidance: relaxed framing instead of an advertising composition, plausible available-light exposure/focus, restrained noise/sharpening only when appropriate, and no blanket grain, compression blocks, cinematic grading or aggressive HDR. Bright daylight may remain clean and detailed. Cropping, tilt and motion are possibilities rather than mandatory defects. Explicit pose, mirror/selfie geometry, clothing, hairstyle and same-moment continuity still take precedence over aesthetic defaults.

Portrait-only guidance describes naturally grouped hair strands, contact with clothing, focus-dependent softness and eye catchlights consistent with the existing light. It preserves the approved face, hair-color family, curl/texture, age, skin and recognizable features. It does not require a new hairstyle, add a studio light or exaggerate pores/imperfections. Object/pet/environment-only photos receive camera/background guidance without portrait anatomy instructions or new people.

Backgrounds follow established location/travel context and plausible architectural geometry. The builder no longer assumes every object photo is taken in a mid-sized Pennsylvania city, which could conflict with explicit travel scenes. Blair County photos should retain plausible local scale when that location is established; unspecified surroundings are kept modest rather than filled with an invented iconic skyline. These are generation constraints, not verified photographic geography or guaranteed exact architecture.

Canonical reference pixels, character selection, identity screening/retry, text rendering, provider/model selection, image-quality option, resolution, media storage, downloads and budgets are unchanged. Original images are not recompressed, downsampled or post-processed. There are no new model calls or regeneration loops; prompts are somewhat longer, so provider input-token billing may differ slightly. No database migration, secret or production deployment is included.

Regression tests cover portrait, object/travel, another character's mirror composition, mature-content restrictions, reference ordering, unchanged 1024×1536 request size and unchanged returned bytes. The existing character/photo pipeline tests run with mocked providers. Visual acceptance should compare newly generated images with the actual canonical portrait across an outdoor walk, a normal indoor scene and a low-light scene: look for casual framing, context-appropriate exposure, recognizable identity, coherent background and natural hair/eye detail. Clean daylight photos should not all become grainy; no image should be marked visually accepted merely because its generation succeeded.
