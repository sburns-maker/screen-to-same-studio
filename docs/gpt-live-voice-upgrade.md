# GPT-Live custom voice upgrade — staged foundation

## Implemented on this branch

- Five character-specific fictional adult prompt-to-voice descriptions; Tess is light, articulate, expressive, American and explicitly **not husky**.
- `createCharacterVoiceCandidate`: authenticated, existing developer-permission gated, explicit-confirmation endpoint using official `POST /v1/audio/voices` (`type: "prompt"`). Requires server `ENABLE_VOICE_DESIGN=true` and `OPENAI_API_KEY`. Does **not** generate on page load. Does **not** mark candidates approved.
- `gptLiveSessionConfig`: typed saved per-character voice IDs via server environment variables `GPT_LIVE_VOICE_TESS`, `GPT_LIVE_VOICE_MAYA`, etc., gated by `ENABLE_GPT_LIVE_CALLS=true`. Refuses missing IDs and ordinary preset names.
- Regression tests for fail-closed configuration and distinct descriptions.

## What is NOT implemented yet

This branch deliberately does **not** connect a call to GPT-Live. The existing Phase 5 call screens and turn-based speech pipeline remain unchanged. `ENABLE_GPT_LIVE_CALLS` must stay **false** until actual authenticated session authorization, WebRTC negotiation, delegation to the existing `runTurn` engine and playback-acknowledgement semantics, usage reservations, privacy handling, and end-to-end device tests are implemented. A prompt that instructs the live model to delegate does **not** create that integration.

Custom voice IDs generated from descriptions currently work with `gpt-live-1`, **not** the regular `generateSpeech` speech endpoint used by Phase 5. Do not insert `voice_...` into `VOICE_TESS` and expect it to work. Custom voice creation cannot be verified without the project's own API key and access.

## Steps to audition Tess

1. Review OpenAI [custom voice guide](https://developers.openai.com/api/docs/guides/custom-voices) and [voice WebRTC guide](https://developers.openai.com/api/docs/guides/voice-webrtc). Review synthetic-voice disclosure requirements and the project's API spend controls.
2. In a developer-authorized setup, explicitly enable `ENABLE_VOICE_DESIGN=true`. Request candidate creation with `character=tess`, `variant=natural|refined|playful`, and confirmation `CREATE CUSTOM VOICE`. The server returns a stored ID; no live playback is generated by creation.
3. Audition saved candidate IDs in GPT-Live's voice Playground using the same sarcastic, affectionate and everyday prompts. Live auditions incur voice-session charges.
4. Choose one; configure `GPT_LIVE_VOICE_TESS=voice_...` on the **server**, not in client JavaScript. Do not enable GPT-Live calls yet.
5. Wire GPT-Live client delegation to the authenticated phone-call ledger and existing character backend in a follow-up implementation. Preserve original Phase 5 phone operation, consent, transcript, memory, plan and quiet-hour protections. Test first on staging with strict voice budget caps, then deploy intentionally.

## Current scope/limits

No provider request, charge, database migration, or production change is performed by GitHub commits. No verified WebRTC connection or spoken output is claimed. Provider costs and account entitlement need actual project validation.
